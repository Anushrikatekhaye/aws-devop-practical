# Deployment Guide

## 1. Prerequisites

- AWS account and a region (default `ap-south-1`)
- Terraform >= 1.5, AWS CLI v2, Git
- A GitHub repository containing this project

## 2. One-time bootstrap (remote state)

Create an S3 bucket (versioned, encrypted) and a DynamoDB table (partition key `LockID`, string) for Terraform state:

```bash
aws s3api create-bucket --bucket <tfstate-bucket> --region ap-south-1 \
  --create-bucket-configuration LocationConstraint=ap-south-1
aws s3api put-bucket-versioning --bucket <tfstate-bucket> --versioning-configuration Status=Enabled
aws dynamodb create-table --table-name <tf-lock-table> \
  --attribute-definitions AttributeName=LockID,AttributeType=S \
  --key-schema AttributeName=LockID,KeyType=HASH --billing-mode PAY_PER_REQUEST
```

## 3. GitHub → AWS authentication (OIDC)

1. In IAM, add an identity provider: `https://token.actions.githubusercontent.com`, audience `sts.amazonaws.com`.
2. Create a role with this trust policy (replace placeholders) and attach permissions for the services in this stack (EC2, ELB, Auto Scaling, RDS, S3, IAM, Secrets Manager, ACM, Route 53, SSM read, plus access to the state bucket and lock table). Start with `PowerUserAccess` + IAM write for a lab; tighten for real use.

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Principal": {"Federated": "arn:aws:iam::<ACCOUNT_ID>:oidc-provider/token.actions.githubusercontent.com"},
    "Action": "sts:AssumeRoleWithWebIdentity",
    "Condition": {
      "StringEquals": {"token.actions.githubusercontent.com:aud": "sts.amazonaws.com"},
      "StringLike": {"token.actions.githubusercontent.com:sub": "repo:<GITHUB_USER>/<REPO>:*"}
    }
  }]
}
```

3. In the repo settings add:
   - **Secrets:** `AWS_ROLE_ARN`, `TF_STATE_BUCKET`, `TF_LOCK_TABLE`
   - **Variables (optional):** `AWS_REGION`, `ENVIRONMENT`, `DOMAIN_NAME`, `ROUTE53_ZONE_ID`
   - **Environment:** create `production` and add required reviewers for a manual approval gate before apply.

## 4. Deploy

**Via CI/CD:** push to `main`. The workflow runs Validate → Plan → (approval) Apply → health checks.
Pull requests run Validate and Plan only.

**Manually:**

```bash
cd terraform
cp terraform.tfvars.example terraform.tfvars
terraform init -backend-config=backend.hcl   # or -backend=false for a local trial
terraform apply
```

First apply takes ~15–20 minutes (RDS Multi-AZ is the slowest part).

## 5. HTTPS / domain

| Situation | What to do |
|---|---|
| No domain yet | Leave `domain_name = ""`. A self-signed cert is imported into ACM. Use the ALB DNS name; accept the browser warning. |
| Domain in Route 53 | Set `domain_name` and `route53_zone_id`. Cert validation and alias record are automatic. |
| Domain elsewhere | Set `domain_name`. During apply, add the CNAME from `terraform output acm_validation_records`, then point your domain's CNAME at the ALB DNS name. |

## 6. Validate the deployment

```bash
URL=$(terraform output -raw application_url)
curl -ik  $URL/health          # 200 {"status":"ok"}
curl -sk  $URL/db              # {"database":"connected","mysql_version":"8.0.x"}
curl -sI  http://$(terraform output -raw alb_dns_name)/   # 301 -> https
```

Console checks:

- EC2 → Target Groups: all targets **healthy**, spread across both AZs
- RDS: status *Available*, Multi-AZ *Yes*, publicly accessible *No*, encrypted *Yes*
- Secrets Manager: `<project>-<env>/db-credentials` exists
- S3: objects appear under `alb/AWSLogs/...` in the logs bucket a few minutes after traffic
- Session Manager: connect to an instance, run `systemctl status app`

Scaling/HA test: terminate one instance in the ASG; the ALB keeps serving and the ASG replaces it.

## 8. Teardown

```bash
terraform destroy
```

or run the workflow manually with **destroy** enabled. Defaults skip the final DB snapshot and allow bucket force-delete; set `db_skip_final_snapshot = false` for anything you want to keep.

## 9. Security notes

- No secrets in Git: DB password generated by Terraform and stored only in Secrets Manager (it is also present in Terraform state, so keep the state bucket private and encrypted).
- Instances have no public IPs and no inbound SSH; admin access via SSM.
- IMDSv2 enforced, EBS and RDS encrypted, S3 public access blocked, TLS-only bucket policies.
- Production hardening ideas: KMS CMKs, WAF on the ALB, VPC endpoints for S3/Secrets Manager, one NAT per AZ (`single_nat_gateway = false`), RDS `manage_master_user_password` with rotation.
